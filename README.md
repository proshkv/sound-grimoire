# Звуковой Гримуар — архив аудиозаписей

Один файл, без сборки, без сервера. Открывается прямо в браузере.

## Структура

```
index.html          — вся страница (разметка + стили + логика)
tracks.json          — список записей: название, автор, жанр, файл, длительность
audio/               — сюда кладите свои mp3/wav-файлы (папку нужно создать)
  track1.mp3
  track2.mp3
  ...
```

## Как добавить свои записи

Список треков больше не хранится внутри `index.html` — он живёт в отдельном
файле `tracks.json` рядом со страницей. Откройте его и отредактируйте
массив:

```json
[
  { "id": "moya-zapis", "title": "Название трека", "author": "Автор", "genre": "Жанр", "file": "audio/moya-zapis.mp3", "duration": "3:45", "added": "2024-08-22" }
]
```

- `id` — короткий идентификатор записи для прямой ссылки, латиницей, без
  пробелов (необязательно; если не указать, страница сама сгенерирует его
  из названия). Подробнее — в разделе «Прямые ссылки на записи» ниже;
- `title` — название трека;
- `author` — автор/исполнитель (необязательно; если не указать, просто не
  будет показан);
- `genre` — вкладки жанров строятся автоматически из этого поля, отдельно
  их прописывать не нужно; в списке жанр показывается бейджем сбоку от
  названия;
- `file` — путь к файлу относительно `index.html` (проще всего держать все
  аудио в папке `audio/` рядом со страницей) или полная ссылка `https://...`;
- `duration` — длительность в виде текста `"мм:сс"` (необязательно; если не
  указать, вместо неё покажется `--:--`);
- `added` — дата добавления записи в формате `"ГГГГ-ММ-ДД"` (необязательно;
  используется для сортировки «по дате добавления» и отображается рядом с
  жанром; если не указать, запись просто не будет участвовать в сортировке
  по дате и окажется в её конце).

Страница сама загружает `tracks.json` через `fetch()` при открытии.

## Страница «Мои треки»

Кнопка **«Мои треки»** в шапке `index.html` ведёт на отдельную страницу
`my-tracks.html` — «Треки pro_Oshkv». Она использует тот же `tracks.json`,
но показывает только записи, у которых поле `author` равно `pro_Oshkv`
(регистр не важен). Чтобы запись попала на эту страницу, укажите в
`tracks.json`:

```json
{ "title": "...", "author": "pro_Oshkv", "genre": "...", "file": "audio/...", "duration": "...", "added": "..." }
```

На странице «Мои треки» есть кнопка «Весь архив» — она ведёт обратно на
`index.html`. Имя автора, по которому идёт фильтрация, задано в
константе `MY_AUTHOR` в начале скрипта `my-tracks.html` — при желании его
можно поменять там.

## Прямые ссылки на записи

Каждую запись можно открыть по прямой ссылке вида:

```
https://ваш-сайт/index.html?track=moya-zapis
```

При открытии такой ссылки страница сразу находит нужную запись, прокручивает
к ней список и включает воспроизведение (если браузер не заблокировал
автовоспроизведение без взаимодействия — тогда запись просто будет выбрана
и подсвечена, останется нажать play).

Идентификатор в ссылке (`?track=...`) берётся из поля `id` в `tracks.json`.
Если для записи `id` не указан, страница сама собирает его из названия —
но такой автоматический id надёжнее не менять местами записи в файле и
проверять ссылку после правки `tracks.json`. Проще всего прописать `id`
вручную для тех записей, ссылками на которые собираетесь делиться.

Ссылкой удобно делиться двумя способами:
- нажать на иконку 🔗 рядом с записью в списке — ссылка на неё скопируется
  в буфер обмена;
- или просто скопировать адрес из адресной строки браузера: пока играет
  запись, адрес страницы сам обновляется на прямую ссылку на неё.

Страница «Мои треки» (`my-tracks.html`) работает так же, но своя прямая
ссылка вида `my-tracks.html?track=...` сработает только для записей автора
`pro_Oshkv` — ссылки на чужие записи там просто игнорируются.

## Избранное

У каждой записи есть кнопка-сердечко ♥. Клик добавляет запись в избранное,
повторный клик — убирает. Вкладка **«♥ Избранное»** рядом с жанрами
показывает только отмеченные записи.

Избранное хранится прямо в браузере (в `localStorage`), без учётных
записей и сервера — то есть оно **своё для каждого браузера/устройства**:
- если сайтом пользуются несколько человек с разных устройств (или в
  разных браузерах на одном устройстве) — у каждого будет свой список
  избранного, они не смешиваются;
- при этом `index.html` и `my-tracks.html` используют один и тот же
  список (это одна и та же страница/сайт с точки зрения браузера);
- если очистить данные сайта в браузере или открыть сайт в режиме
  инкогнито — избранное сбросится;
- полноценного «своего избранного под логином» без сервера с базой
  данных не бывает — здесь это именно локальное избранное конкретного
  браузера, а не аккаунт.

## Сортировка списка

Над списком, рядом со строкой поиска, есть выпадающий список сортировки:

- «По умолчанию» — порядок как в `tracks.json`;
- «Название (А–Я)» — по алфавиту названия;
- «Исполнитель (А–Я)» — по алфавиту автора/исполнителя;
- «Длительность» — от самых коротких записей к самым длинным;
- «Дата добавления» — от новых записей к старым (используется поле `added`).

Сортировка работает вместе с выбором жанра и поиском — можно, например,
выбрать главу «Эмбиент» и отсортировать её по длительности.

### Важно: локальный просмотр через двойной клик не сработает

Если открыть `index.html` двойным щелчком (адрес в браузере начинается с
`file://`), браузер из соображений безопасности заблокирует загрузку
`tracks.json` — список будет пустым, а страница покажет объяснение.
Чтобы проверить сайт локально, поднимите простой сервер в этой папке,
например:

```
python3 -m http.server
```

и откройте `http://localhost:8000`. При выкладывании на GitHub Pages или
Cloudflare Pages (см. ниже) всё работает без этой возни — там сайт всегда
открывается по `https://`, а не `file://`.

## Как выложить бесплатно и навсегда

**Вариант 1 — GitHub Pages**
1. Создайте репозиторий на GitHub, загрузите `index.html` и папку `audio/`.
2. В настройках репозитория откройте вкладку *Pages*, выберите ветку
   `main` и папку `/root`.
3. Сайт появится по адресу `https://ваш-логин.github.io/название-репозитория`.

**Вариант 2 — Cloudflare Pages**
1. Зарегистрируйтесь на pages.cloudflare.com, создайте проект.
2. Подключите тот же GitHub-репозиторий или загрузите файлы напрямую.
3. Получите адрес вида `название.pages.dev`.

Оба варианта бесплатны для статических сайтов и не имеют срока действия —
достаточно, чтобы репозиторий/проект оставался активным.

## Если аудиофайлы тяжёлые

GitHub не любит отдельные файлы больше ~100 МБ и большие репозитории.
Если архив крупный, разумно хранить mp3 на внешнем файловом хостинге и
просто указывать в `file` полную ссылку на файл (`https://...`) — плеер
одинаково работает и с локальными путями, и с внешними URL.
